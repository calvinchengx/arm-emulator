# v0.4.0

The theme is a **new provider**: `Microsoft.Fabric/capacities`. Create, SKU,
suspend, resume and `list_usages` now happen here, the way they do on
`management.azure.com`, and fabric-emulator lists those capacities on
`GET /v1/capacities` when pointed at this process. Nothing else on the ARM
surface changed.

Upgrade from v0.3.1 if you want Fabric capacities locally. Stay if you don't.

---

## Microsoft.Fabric/capacities

Capacities are ARM resources. The Fabric REST plane only lists them and
assigns workspaces; create, SKU, suspend and resume live on ARM. This release
is that ARM half.

What it does:

- create / get / list / patch / delete, inside an existing resource group
- F-series SKUs F2–F2048, tier `Fabric`
- suspend / resume
- check-name and list SKUs (subscription-wide and per capacity)
- `list_usages` as **provisioned** CU (an Active F64 counts as 64; paused
  counts as 0)
- `properties.overage` round-trips (`Enabled`/`Disabled` and the threshold)
  and does not burst or throttle

What it does not do, on purpose: job metering, throttling, billing. SKU is a
label and a CU count for `list_usages`. The compute bound is still
fabric-emulator's unbuilt job-queueing work.

A new capacity is assigned a Fabric REST GUID at create. ARM's own document
does not carry it — Azure doesn't either — so it travels on
`GET /_family/capacities`, the same localhost-coordination exception as the
authorization feed. fabric-emulator polls that feed when `FABRIC_ARM_URL` is
set.

The full contract is in [10-fabric-provider.md](../10-fabric-provider.md).

## Witnesses, not a second reading of the spec

Four independent client stacks drive the provider unmodified:

| Client | Surface |
|---|---|
| `armfabric` (Azure Go SDK) | create/get/list/update/suspend/resume/delete, check-name, `list_usages`, overage |
| `azure-mgmt-fabric` 1.1.0b1 | create/get/list/`list_usages`/delete, overage, check-name |
| `@azure/arm-fabric` 1.0.0 | create/get/list/delete and check-name (`api-version` 2023-11-01; that package has no `list_usages` or `overage`) |
| `Azure.ResourceManager.Fabric` 1.0.0 | the same as JavaScript, against a custom `ArmEnvironment` |

CI `sdks` is the Python / JavaScript / .NET witness. Go lives in `go test`.

## Also since v0.3.1

entra-emulator **0.6.0** is the in-process STS this binary links, matching
the family BOM. Docs now point every consumer at
[azure-emulators](https://github.com/calvinchengx/azure-emulators) for
composition rather than duplicating a stack here.

## Upgrading

Pull `0.4.0`. Existing resource groups, role assignments and vaults are
unchanged. A family compose that wants fabric-emulator to list ARM-created
capacities also needs a fabric-emulator release that reads `FABRIC_ARM_URL`
— that consume path is not in fabric 0.23.0.
