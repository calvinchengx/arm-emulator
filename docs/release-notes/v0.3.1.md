# v0.3.1

One fix: **the container healthcheck works again in the documented
configuration.** Upgrade from v0.3.0 if you run the image.

## The bug

v0.3.0 changed `arm-emulator healthcheck` to verify TLS by pinning the
emulator's self-signed certificate from the data directory, in response to
CodeQL's `go/disabled-certificate-check`. It reads better, and it only works
when there *is* a data directory.

The documented throwaway configuration — used by this repo's own compose file
and by the family BOM — sets `ARM_DATA_DIR=""` so that nothing is written to
disk and `docker compose down` leaves no volume behind. The certificate is then
generated in memory, and the healthcheck, a separate process, has no file to
pin. Every container in that configuration went **permanently unhealthy**, and
anything waiting on `condition: service_healthy` blocked behind it:

```
arm-emulator-1  http: TLS handshake error from 127.0.0.1:58752: remote error: tls: bad certificate
FAIL: the stack never became healthy
```

It reached a release because the repo's own CI checks that `make up` and
`make status` work, and those probe the server from the host rather than
running the container's own HEALTHCHECK. The family chain in azure-emulators,
which waits on container health, caught it on the first compose after the tag.

## The fix

The healthcheck no longer verifies the certificate, and that is now a decision
rather than an oversight. What it defends is a loopback connection to a process
in the same container, whose certificate this same binary generated moments
earlier; there is nothing between the two to defend against. The alternative is
a healthcheck that fails for the recommended configuration, which is worse than
the alert it silences. The sibling emulators reached the same conclusion, and
the CodeQL finding is dismissed there for the same reason.

The reasoning is written into the function, so the next reader does not
rediscover the pinning idea and reintroduce this. A test covers the case that
broke: a probe against a server holding an in-memory certificate must succeed.

`tlscert.Pool` is removed with it — nothing used it once the healthcheck
stopped, and dead code kept alive by its own test is how the coverage gate ends
up measuring the wrong thing.

## Upgrading

Pull `0.3.1`. Nothing on the ARM surface changed, and there is no reason to
stay on `0.3.0`.
