# v0.3.0

Nineteen commits, and the theme is **the authorization model stops being a
shape and starts being a decision.** Deny assignments override role
assignments. ABAC conditions are parsed and evaluated instead of stored
verbatim. Vault deletes leave the vault recoverable. Custom roles enforce the
scopes they declare. Asynchronous operations really stay in progress until the
clock says otherwise.

The parity map reaches **25/25 green, every claim independently evidenced** —
no row rests on our own reading of the contract at both ends. Four independent
client stacks now drive the emulator: Microsoft's Go SDKs, the packaged `az`
CLI, and the Python, JavaScript and .NET management SDKs.

Two behaviour changes need reading before you upgrade. Everything else is
additive.

---

## Behaviour change: `DELETE` on a vault no longer destroys it

Real Key Vault does not destroy a vault on delete — it becomes recoverable,
keeps holding its name, and dies only on an explicit purge or when its
retention window lapses. The emulator now does the same.

**What breaks:** a test that deletes a vault and immediately recreates it under
the same name now gets `409 VaultAlreadyExists`, because the name is still
held. That is what Azure does, and it is the whole point — an emulator that
hard-deletes teaches the opposite of what production teaches.

**Migrating**, whichever fits:

- Recreate with `properties.createMode: "recover"` to bring the vault back with
  its configuration intact.
- `POST .../deletedVaults/{name}/purge` (or `az keyvault purge`) to free the
  name for a fresh create.
- Advance the emulator clock past `scheduledPurgeDate` — the retention window
  is 7-90 days, default 90, set by `ARM_VAULT_RETENTION_DAYS`.

## Behaviour change: deletes and creates are asynchronous, as ARM's are

ARM answers long-running operations with a polling contract, and both of its
shapes are implemented:

| Operation | Was | Now |
|---|---|---|
| `DELETE` resource group | `200` | `202` + `Location` to poll, `204` when there was nothing to delete |
| `PUT` vault | `200` | `201` + `Azure-AsyncOperation` status document, `provisioningState: Creating` until it completes |

Microsoft's own pollers handle this unchanged — `armresources` and
`armkeyvault` genuinely spin, observing `InProgress` before `Succeeded`. A
hand-rolled client that asserted `200` needs updating. Completion runs on the
controllable clock (`ARM_LRO_DELAY_SECONDS`, default 0), so nothing sleeps.

## Deny assignments

The one part of Azure's model that takes access away, and it now really does.

They are **read-only over ARM**, as in Azure: no customer creates one —
Blueprints, managed applications and deployment stacks do — so `GET` and list
work at any scope and every write is refused with a message saying where they
come from. Seeding goes through `POST /_emulator/denyassignments`, the honest
place for something with no public create API.

And they **win**: a deny beats every role assignment granting the same action.
Wildcards spanning segment boundaries, `notDataActions` carve-outs, the
all-principals GUID, `excludePrincipals`, group principals and
`doNotApplyToChildScopes` all decide the outcome, and the verdict reaches the
data planes through the family feed.

## ABAC conditions, evaluated

A `condition` narrows a role assignment — "this role, but only for secrets
whose name starts with `app-`". Previously stored and handed back unread, which
teaches a developer their condition works when nothing has ever tested it.

The version 2.0 language is now parsed and evaluated: `ActionMatches` /
`SubOperationMatches` guards, `@Resource` / `@Request` / `@Principal` /
`@Environment` attributes, the string, numeric, datetime, bool and GUID
operators, `Exists`, all four `ForAnyOf…`/`ForAllOf…` quantifiers, and
`AND` / `OR` / `!()`.

Two rules worth knowing, both Azure's: a **missing attribute fails its
comparison, negative operators included** — which is exactly why real
conditions carry an `!(ActionMatches{…}) OR …` guard — and a multi-valued
attribute compared without a quantifier is false, because the author has not
said whether they meant any or all.

**A malformed condition is now refused at write time** (`InvalidCondition`
naming the offending position, `InvalidConditionVersion` for anything but
`2.0`) rather than stored. If you have been writing junk into that field, this
will start failing, which is the intent: an assignment that looks constrained
and is not is worse than no assignment.

`POST /_family/authorization/evaluate` answers the whole question in one call —
deny overrides, then a role must grant the action, then its condition must
hold — and reports which of those decided it.

## Custom role definitions

Real CRUD at `PUT`/`DELETE .../roleDefinitions/{guid}`, listed and `$filter`ed
beside the built-ins. **`assignableScopes` is enforced**, not merely stored: an
assignment outside them is refused. Built-ins cannot be overwritten or deleted,
display names are unique, and a definition still carrying assignments cannot be
removed. Its `dataActions` flow through the family feed, so a role a caller
invented genuinely grants data-plane access. `az role definition create` writes
them.

## Also new on the ARM surface

- **`GET /subscriptions/{sub}/resources`** — the subscription-wide tracked
  resource list, with `$filter` for `resourceType eq` and `name eq`. The CLI
  consults it whenever a command names a resource without its group, so
  `az keyvault delete --name v` now works instead of demanding the group.
- **Deleted-vault reads**: `deletedVaults` at the subscription and under a
  location, with `deletionDate` and `scheduledPurgeDate`.

## Four client stacks, and the two defects they found

Python, JavaScript and .NET management SDKs now drive the emulator in CI
(`e2e/sdks/run.py`), alongside the Go SDKs and the `az` CLI. This is not
redundancy: an emulator that only ever meets one SDK gets shaped by that SDK's
habits, and every test keeps passing because nothing else looks. Writing them
found two real defects that Go had no way to see.

- **A redirect that cost clients their credentials.** Microsoft's JavaScript
  SDKs join their endpoint to an ARM scope without normalizing, so every
  request begins `//subscriptions/…`. `ServeMux` answered with a `301` to the
  clean path, and a client following a redirect drops its `Authorization`
  header — an authenticated request arrived anonymous and came back `401`. Real
  ARM serves the doubled slash, and now so does this emulator.
- **A certificate macOS refuses to trust.** The self-signed certificate was
  valid for ten years; Apple rejects any TLS server certificate over 825 days,
  so no .NET client on a Mac could verify it *even when the developer
  deliberately trusted the file*. It is **397 days** now. An existing data
  directory keeps its old certificate — delete `tls/` inside it to reissue.

Both are pinned by Go unit tests, so a regression fails in seconds rather than
only in the cross-language job.

## Security

The `healthcheck` subcommand verified nothing: it disabled certificate checking
outright. It now **pins the emulator's own certificate** as its trust root, and
says so plainly when it cannot find one rather than trusting silently.

## Honesty about the ledger

Rows were being scored in two places at once — counted as gaps in the parity
tables while also declared out of scope below them — and the witness checker
was skipping sections by names it inherited from a sibling repo, so it silently
graded nothing in some of them. A row now appears in exactly one place, the
checker names this repo's own sections, and every 🟢 claim carries a witness of
a stated kind. The number moved because the bookkeeping was fixed, not because
the emulator changed.

## Upgrading

- Handle the two behaviour changes above if you delete vaults or resource
  groups directly rather than through an SDK poller.
- Delete `tls/` in your data directory to pick up a certificate macOS and
  Windows will accept.
- `entra-emulator` **v0.4.1** or later, unchanged from v0.2.0.
