# v0.2.0

Nineteen commits with one theme running through them: **arm-emulator stops
being a repo that happens to work with the family and becomes one the family
can pin.** The default IDs move to realistic GUIDs that match entra-emulator's
seeds, the vault resource serves its full configuration so a data plane can
learn purge protection from ARM rather than guessing, and the repo picks up the
docs site, code scanning and BOM-pinned images the rest of the family already
had.

One breaking change, called out first. Everything else is additive.

---

## Breaking: realistic opaque GUIDs (`feat(config)!`)

The default subscription and tenant were patterned placeholders. They are still
fixed and deterministic; only the values changed.

| Setting | Old | New |
|---|---|---|
| `ARM_SUBSCRIPTION_ID` | `00000000-0000-0000-0000-000000000001` | `6082bfda-63d0-46f4-8272-ae9195139feb` |
| `ARM_TENANT_ID` | `11111111-1111-1111-1111-111111111111` | `6f89cf12-978b-4d23-ac18-9ef0c127cf87` |

A uniform GUID is a weak test oracle: it survives segment transposition and
most mis-slicing, so parsing bugs pass unnoticed. These do not.

**The tenant is not a free choice.** It tracks `entra-emulator` **v0.4.0+**,
whose seeded tenant moved to the same value. If the two disagree the
quickstart's client-credentials exchange fails, and a v0.2.0 arm against a
pre-v0.4.0 entra fails the same way in reverse. Do not mix them.

Azure's built-in role definition IDs — Owner, Contributor, Reader and the Key
Vault roles — are real Azure identifiers and are unchanged.

**Migrating:** update any issuer or authority URL embedding the tenant, and any
subscription id your tests name. The mapping above also lives in
[`docs/04-configuration.md`](../04-configuration.md).

## The vault resource serves its full configuration

Purge protection and the soft-delete retention window join the access policies
and the RBAC switch on the family feed. In Azure these are properties of the
ARM resource, so a Key Vault data plane should learn them from ARM rather than
carry its own opinion — `azure-keyvault-emulator` now does.

## Runnable, and pinned

- **The image's `/data` is writable by the nonroot uid it runs as.** It was
  owned by root, so a fresh volume mounted there left the server unable to open
  its SQLite file — the container exited 1 before serving anything. Distroless
  has no shell, so the directory is created in the build stage and copied in
  with the right ownership.
- **`ENTRA_EMULATOR_VERSION` is pinned to the BOM**, not `:latest`. Tracking
  `:latest` is how an upstream release reaches CI unannounced; drift testing
  still works by overriding the variable.
- **Compose seeds the tenant arm-emulator expects**, so the pair comes up
  without the discovery 404 that a default-seeded entra would produce.

## Docs, and the gates around them

- A **docs site on GitHub Pages**, with self-hosted coverage and witness badges
  measured in CI rather than trusted from a third party.
- **CodeQL and Dependabot** now cover the docs site as well as the Go module.
  Three code-scanning findings are fixed in this release: an incomplete
  sanitizer in the docs generator that emitted unparseable YAML for any title
  containing a backslash, and two workflows running with an unrestricted
  `GITHUB_TOKEN`.
- PR builds no longer cancel a queued Pages deploy.

## Internal

`VaultAccessPolicies` is removed, superseded by `VaultConfigAt`. It was dead
code whose tests were keeping it fully covered while the live function sat at
38%, pulling the total below the 98% floor — the coverage gate was measuring
the wrong thing.

## Upgrading

Change the two IDs above if you name them, and make sure your `entra-emulator`
is **v0.4.0 or later**. Nothing else in the ARM surface changed.
